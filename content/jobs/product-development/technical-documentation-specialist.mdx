# Technical Documentation Specialist

### The Mission

Undocumented software is untrusted software. At Chemist3 Labs, our platforms are deployed into environments where operators cannot call a support hotline, where engineers integrating our APIs cannot afford to guess at parameter behavior, and where system administrators need runbooks that work the first time under incident pressure. The Technical Documentation Specialist is the person who ensures that every system, API, workflow, and operational procedure is documented with the precision, clarity, and completeness that mission-critical deployments demand.

This is not a role for writers who can describe what a button does. This is a role for technical communicators who can read source code, interrogate engineers, test systems hands-on, and produce documentation that enables an operator to deploy, configure, troubleshoot, and extend Chemist3 systems without guessing. The documentation you produce is as much a part of the product as the code itself — and it will be judged by the same standard of correctness.

If your experience is limited to polishing marketing copy or reformatting wiki pages, this role will be a mismatch. If you have written API specifications that developers actually use, runbooks that operators actually follow during incidents, and architecture documents that actually reflect how the system works, you understand the craft we are looking for.

### Core Responsibilities

- Author and maintain comprehensive API documentation: endpoint references, request/response schemas, authentication flows, error codes, rate limiting behavior, and integration quickstart guides.
- Produce system architecture documentation: component diagrams, data flow descriptions, dependency maps, and deployment topology references that reflect the actual state of production systems.
- Write operational runbooks for deployment, configuration, backup/restore, upgrade, and incident response procedures — tested against real systems to ensure step-by-step accuracy.
- Develop operator manuals for client-facing platforms: workflow guides, feature documentation, configuration references, and troubleshooting decision trees.
- Maintain documentation infrastructure: static site generators, versioning schemes, search indexing, content organization taxonomies, and automated documentation generation from code annotations and API schemas.
- Collaborate with engineers to extract and document tribal knowledge — turning hallway conversations and Slack threads into structured, discoverable, and maintainable documentation.
- Conduct documentation audits: identifying gaps, stale content, and inaccuracies through systematic review cycles and user feedback analysis.
- Establish and enforce documentation standards: style guides, terminology glossaries, template libraries, and review workflows that maintain quality and consistency at scale.

### What We Look For

**Technical / Domain Competencies:**
- Strong technical writing fundamentals: information architecture, audience analysis, progressive disclosure, and structured authoring.
- Ability to read and comprehend source code in at least one systems language (Python, Go, TypeScript, Java) — enough to verify documentation accuracy against implementations.
- Experience with documentation tooling: Markdown/MDX authoring, static site generators (Docusaurus, MkDocs, GitBook, Nextra), API documentation generators (OpenAPI/Swagger, Redoc), and docs-as-code workflows.
- Familiarity with diagramming tools (Mermaid, PlantUML, Excalidraw, draw.io) for producing architecture and workflow visualizations.
- Understanding of REST API conventions, authentication mechanisms, and common integration patterns — enough to write accurate API guides without engineering hand-holding.
- Experience documenting infrastructure systems, DevOps tooling, or security procedures is a strong signal.
- Prior work in technical documentation for developer tools, enterprise platforms, or defense/intelligence systems.

**Mindset & Attributes:**
- Obsessive accuracy — you verify every command, every parameter, and every screenshot against the actual system before publishing.
- Engineering empathy — you understand what information a developer or operator needs, in what order, and at what level of detail.
- Systematic maintenance discipline — you treat documentation as living infrastructure that requires ongoing investment, not a one-time deliverable.
- Comfort with ambiguity — you can extract coherent documentation from systems and engineers that have never been documented before.
- Strong editorial judgment — you know when a topic needs a quickstart guide versus a reference manual versus an architecture overview.

### Operating Principles

- **Outcomes Over Deliverables:** Documentation is successful when operators and developers can accomplish their tasks without needing to ask an engineer for help. Page count is not a metric.
- **Zero Layering:** Documentation specialists work directly with the engineers who build the systems and the operators who use them. Information does not pass through intermediaries.
- **Extreme Ownership:** If a runbook fails during an incident because a step was inaccurate, you own that failure — not the engineer who forgot to tell you about a change.
