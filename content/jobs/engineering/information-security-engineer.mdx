# Information Security Engineer

### The Mission

Chemist3 Labs operates in environments where a security failure is not a PR problem — it is a mission failure. Our clients entrust us with their most sensitive data, deploy our systems inside their most protected networks, and expect our engineering to withstand threat actors with nation-state capabilities. The Information Security Engineer is the operator who ensures that trust is warranted — by building security into every layer of our systems, not bolting it on after the fact.

This is not a compliance checkbox role. You will conduct threat modeling against real attack surfaces, harden production systems against sophisticated adversaries, perform vulnerability assessments across codebases and infrastructure, and design security architectures that protect data in transit, at rest, and in use. You will work across network boundaries, cloud environments, air-gapped deployments, and client infrastructure — each with its own threat profile and compliance requirements.

If your security experience is limited to running scanners and writing audit reports, this role will overwhelm you. If you think like an attacker, build like a defender, and can articulate risk in terms that engineers and executives both understand, you will find this to be the most impactful security role available outside of a three-letter agency.

### Core Responsibilities

- Conduct threat modeling exercises across Chemist3 platforms, client deployments, and internal infrastructure — identifying attack surfaces, trust boundaries, and adversary capabilities relevant to each environment.
- Perform code-level security reviews and static/dynamic analysis across backend services, APIs, web applications, and infrastructure-as-code — catching vulnerabilities before they reach production.
- Design and implement system hardening standards: OS baselines, container security policies, network segmentation rules, and secrets management workflows.
- Build and maintain vulnerability management programs: scanning cadences, CVE triage processes, patching workflows, and risk-based prioritization frameworks.
- Architect authentication and authorization systems: identity providers, RBAC/ABAC models, certificate management, and zero-trust network access patterns.
- Develop and execute incident response procedures: detection rules, forensic playbooks, containment strategies, and post-incident analysis workflows.
- Drive compliance readiness across relevant frameworks (SOC 2, FedRAMP, CMMC, NIST 800-53, ISO 27001) — translating control requirements into engineering implementations rather than documentation exercises.
- Collaborate with Forward Deployed teams to assess and meet client security requirements — including air-gapped deployments, data handling agreements, and security architecture reviews.

### What We Look For

**Technical / Domain Competencies:**
- Deep understanding of application security: OWASP Top 10, injection attacks, authentication bypass, deserialization vulnerabilities, SSRF, and supply chain attacks.
- Strong Linux systems security: audit frameworks (auditd, SELinux/AppArmor), kernel hardening, filesystem permissions, and process isolation.
- Network security proficiency: firewall design, IDS/IPS, TLS configuration, certificate pinning, DNS security, and network traffic analysis (Wireshark, tcpdump).
- Experience with cloud security posture management (AWS IAM, GCP Security Command Center, Azure Defender) and container security (Falco, Trivy, OPA/Gatekeeper).
- Proficiency in scripting (Python, Bash, Go) for security automation, custom tooling, and exploit proof-of-concept development.
- Familiarity with cryptographic implementations: key management, encryption at rest/in transit, PKI, HSMs, and common cryptographic pitfalls.
- Relevant certifications (OSCP, GPEN, GCIH, CISSP) are valued but not required — demonstrated capability matters more than credentials.

**Mindset & Attributes:**
- Adversarial thinking — you instinctively consider how a system can be abused, not just how it is designed to be used.
- Engineering-first approach to security — you build automated guardrails, not policy documents that nobody reads.
- Ability to communicate risk clearly to non-security engineers and leadership without resorting to fear-mongering or jargon.
- Deep intellectual curiosity about emerging threats, novel attack techniques, and defensive architectures.
- Comfort operating across classification levels, compliance frameworks, and client security environments with varying maturity levels.

### Operating Principles

- **Extreme Ownership:** Security is not an advisory function. If a vulnerability ships, you own the failure — the detection gap, the process gap, and the remediation.
- **Zero Layering:** You work directly with the engineers writing the code and operating the infrastructure. Security reviews happen in pull requests, not in quarterly audits.
- **Outcomes Over Deliverables:** A hardened production system with zero critical vulnerabilities matters more than a 200-page security policy that no one follows.
