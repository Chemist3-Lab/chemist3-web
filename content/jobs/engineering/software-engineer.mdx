# Software Engineer

### The Mission

Chemist3 Labs builds systems that operate in environments where correctness, performance, and reliability are non-negotiable. The Software Engineer is the engine of that capability — writing the core backend logic, microservices, internal libraries, and platform infrastructure that every other team depends on. You are not building features for a product roadmap. You are building the foundational systems that power mission-critical deployments across defense, enterprise, and intelligence domains.

This role demands engineers who think in systems, not tickets. You will own entire subsystems — from API design through implementation, testing, deployment, and operational monitoring. The code you write will be deployed into environments where bugs have consequences measured in operational failures, not user complaints. We do not ship code that is "good enough." We ship code that is correct, performant, and maintainable — because the engineers who deploy it into the field need to trust it with their professional reputations.

If you thrive in environments where engineering quality is the product, where code review is rigorous, and where you are expected to understand the full stack from database queries to network protocols, Chemist3 will give you the hardest and most rewarding problems of your career.

### Core Responsibilities

- Design, implement, and maintain core platform services — backend APIs, data processing engines, authentication and authorization systems, and inter-service communication layers.
- Build and maintain internal libraries, SDKs, and shared tooling that accelerate development velocity across the organization without sacrificing correctness or performance.
- Own subsystem architecture decisions — data model design, concurrency strategies, caching layers, and API contracts — with full accountability for production behavior.
- Write comprehensive test suites: unit tests, integration tests, contract tests, and performance benchmarks that provide genuine confidence in system behavior under load and failure conditions.
- Participate in rigorous code review, contributing to and maintaining engineering standards that keep the codebase navigable and trustworthy at scale.
- Collaborate with Forward Deployed engineers to understand field requirements and translate them into platform capabilities that serve multiple deployment contexts.
- Investigate and resolve production incidents with systematic root cause analysis — including cross-service debugging, performance profiling, and memory/concurrency analysis.
- Contribute to technical design documents, architecture decision records (ADRs), and internal engineering documentation.

### What We Look For

**Technical / Domain Competencies:**
- Strong proficiency in one or more systems-oriented languages: Go, Rust, Python, TypeScript, Java, or C++.
- Deep understanding of distributed systems concepts: consistency models, consensus protocols, failure modes, idempotency, and backpressure.
- Experience designing and operating RESTful and/or gRPC APIs with well-defined contracts and versioning strategies.
- Proficiency with relational databases (PostgreSQL, MySQL) and familiarity with non-relational stores (Redis, Elasticsearch, DynamoDB) — including query optimization and schema design.
- Comfort with containerized deployment (Docker, Kubernetes) and CI/CD pipelines (GitHub Actions, GitLab CI, Jenkins).
- Familiarity with observability tooling: structured logging, distributed tracing (OpenTelemetry, Jaeger), and metrics systems (Prometheus, Grafana).
- Computer science fundamentals: data structures, algorithms, concurrency primitives, and systems-level understanding of memory management and I/O.

**Mindset & Attributes:**
- Systems thinking — you instinctively consider failure modes, edge cases, and downstream dependencies when designing solutions.
- High engineering standards — you are uncomfortable shipping code that you would not want to debug at 3 AM.
- Intellectual honesty — you acknowledge when you do not know something and seek to understand before implementing.
- Low-ego collaboration — you give and receive direct feedback in code review without taking it personally.
- Self-directed prioritization — you can identify the highest-leverage work without being told where to focus.

### Operating Principles

- **Outcomes Over Deliverables:** Shipping a well-architected service that handles edge cases gracefully matters more than shipping faster by cutting corners that create operational debt.
- **Zero Layering:** Engineers talk directly to other engineers. Technical decisions are made by the people who will implement and maintain them.
- **Extreme Ownership:** If a service you own causes a production incident, you own the response, the fix, and the postmortem — regardless of whether the triggering event was in your code.
