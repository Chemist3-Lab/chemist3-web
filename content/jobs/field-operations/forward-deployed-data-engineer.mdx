# Forward Deployed Data Engineer

### The Mission

Every enterprise client Chemist3 Labs engages has data. Almost none of them have data that is clean, well-documented, or structured in a way that any downstream system can consume without significant engineering effort. The Forward Deployed Data Engineer is the operator who walks into that chaos, maps the terrain, and builds the pipelines that transform raw client data into fuel for Chemist3's analytical engines.

This is not a dashboard-building role. You will reverse-engineer legacy database schemas with no documentation, migrate decades-old data pipelines that nobody understands anymore, wrangle flat files and proprietary formats into normalized structures, and build ingestion systems that operate reliably against data sources that were never designed to be queried at scale. The clients you serve depend on this data for operational decisions — if your pipeline drops records or introduces drift, the consequences are real.

If you have only worked with clean datasets in a data warehouse that someone else built, this role will humble you. If you have survived the horror of undocumented mainframe extracts, hand-coded CSV parsers, and schema migrations across live production systems, you already know what this job demands.

### Core Responsibilities

- Conduct deep-dive data discovery across client environments — profiling databases, flat files, APIs, and legacy systems to map data lineage and identify quality issues before pipeline construction begins.
- Design and implement ETL/ELT pipelines that extract data from heterogeneous sources (relational databases, NoSQL stores, file systems, streaming platforms, proprietary formats) and deliver it in structured, validated form to downstream Chemist3 engines.
- Execute legacy pipeline migrations — decommissioning brittle scheduled jobs, stored procedures, and manual export workflows and replacing them with modern, observable, and maintainable data infrastructure.
- Build schema mapping layers that reconcile conflicting data models across client systems, handling type coercion, key resolution, deduplication, and referential integrity enforcement.
- Implement data quality frameworks: validation rules, anomaly detection, freshness monitoring, and automated alerting that catch pipeline failures before they propagate.
- Operate within client security and compliance constraints — including data residency requirements, PII handling protocols, and audit logging for all data access and transformation operations.
- Produce data dictionaries, pipeline architecture documentation, and operational runbooks that enable client teams to maintain and extend data infrastructure post-engagement.
- Collaborate with Forward Deployed Software Engineers and Deployment Strategists to ensure data pipelines align with application integration requirements and client operational workflows.

### What We Look For

**Technical / Domain Competencies:**
- Expert-level SQL across multiple database engines (PostgreSQL, MySQL, SQL Server, Oracle) with experience in query optimization, schema design, and migration tooling.
- Strong proficiency in Python for data engineering — pandas, SQLAlchemy, Apache Airflow/Dagster/Prefect, and custom ETL scripting.
- Experience with streaming data platforms (Kafka, Kinesis, Pub/Sub) and batch processing frameworks (Spark, dbt, Beam).
- Familiarity with data serialization formats (Parquet, Avro, Protobuf, JSON Lines) and schema evolution strategies.
- Working knowledge of data warehousing patterns (star/snowflake schemas, slowly changing dimensions, incremental loads).
- Experience reverse-engineering undocumented systems — mainframe extracts, legacy ERP exports, proprietary binary formats.
- Prior work in consulting, systems integration, or data migration projects is highly valued.

**Mindset & Attributes:**
- Obsessive attention to data quality — you treat a dropped record or a silent schema change as a production incident.
- Tolerance for messy, ambiguous, and poorly documented data environments — you do not freeze when the documentation does not exist.
- Systematic debugging discipline across the full pipeline stack — source systems, extraction logic, transformation code, and target schemas.
- Strong written communication — you can document a data model so that someone who has never seen the source system can understand it.
- Comfort operating in client environments with access restrictions, compliance requirements, and limited tooling.

### Operating Principles

- **Outcomes Over Deliverables:** A pipeline that reliably delivers accurate data at the cadence the client needs is the only metric. Pipeline diagrams that never reach production are waste.
- **Field-First Engineering:** Client data lives in client environments. You go to the data — the data does not come to you.
- **Extreme Ownership:** If a pipeline you built drops data, you own the incident, the root cause analysis, and the fix — regardless of whether the fault originated in a source system you did not build.
